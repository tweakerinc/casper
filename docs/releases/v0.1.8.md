# Casper v0.1.8

**Product:** Casper · **Base:** CrossPoint Reader 1.5 / rivulet layout core · **Devices:** Xteink X3 & X4 (single dual binary)

**Firmware:** `dist/Casper-v0.1.8.bin` (tag `v0.1.8`)

---

## Highlights

v0.1.8 is a **reader stability and open/leave UX** release on the rivulet layout engine: Lexend Deca + five body sizes, snappier book open, cleaner Back→Home, less SD thrash, and honest leave feedback—without Font Darkness (AA stays a simple on/off).

---

## What’s new

### Fonts & Manage Fonts

- **Built-in families:** **Source Serif 4** (default UI + reader) and **Lexend Deca** (OFL sans; replaces Bitter as the alternate built-in).
- **Reader body sizes:** **10 / 12 / 14 / 16 / 18** pt (was 12–18 only), with migration from older 4-step enums (`casperReaderFontSizePtMigrated`).
- **StyleResolve ladders** updated for Lexend + Source Serif across 10–18 for CSS size steps.
- **SD fonts:** closest-size mapping targets the five reader sizes.
- **Text Anti-Aliasing** remains a separate Style toggle (Manage Fonts → Style).
- **Live AA preview** in Manage Fonts: when AA is on, the sample pane runs a grey multipass so Soft on/off is visible on-device.
- **Font Darkness** was prototyped then **removed** (runtime greyscale knobs without real ink-weight benefit; AA stays the only soft-edge control).

### Book open (Home → reader)

- **Snappy open policy:** if home greys are settled (or Penumbra text home) **and** `book.bin` exists → **no Loading popup**, FAST first page.
- Loading + HALF first page only when greys are still multipassing or the book index is cold (expected long wait).
- Section layout rebuild still shows Loading **inside** the reader when the spine cache misses.
- Partial section caches: serve pages that are already laid out; defer full extension until near the watermark.

### Page turns & background work

- **Neighbor lookahead stop:** if the next spine has no HTML/section cache, stop scanning further spines (previously walked 84→end of book under `RenderLock`, starving buttons).
- Idle prewarm and deferred text AA behavior retained (BW first ink, greys catch up when safe).

### Clippings

- **Selectable word cap raised** from **240 → 768** (harvest + reading-order array). Small fonts put far more words on a page; the old cap stopped Down before the bottom of the page.
- **Saved clip text cap** raised from **512 → 2048** characters so a full-page selection is not truncated on save.
- Heap still soft-caps harvest when free/maxAlloc is low (same headroom math as before).
- **Long-Press Menu → Clipping Tool:** Confirm long-press opens word-select create flow (not the stored list).
- **Double-Press Menu:** two quick Confirm taps run the same action list (prefer this or long-press Confirm for Clipping Tool; Back long-press fights cancel-on-Back in the tool).
- **Long-Press Back:** same action list (default Off). Short Back still goes Home.
- **Clip OOM (issue #4):** harvest prefers 1 page / ≤400 words with heap gates; no SD mini-kern prewarm during harvest or clip paint; framebuffer snapshot skipped under pressure; soft toast if open refused.
- **Back→Home heap free (issue #5):** wait for render idle before Saving chrome and before font-cache free; harden FontDecompressor free/realloc (null before free) so leave cannot race a mid-decompress free.

### Back → Home

- **Hard HALF scrub** on Home resume from reader / settings / library / menu / etc. so soft FAST children do not leave residual on the home plate. Menus and settings stay FAST for snappy navigation; Home is the cleanup hub.
- **Recents progress cache:** no double SD warm of all rows; on reader leave update **only the current book’s** % in RAM; resume reuses other books by path.
- **Exit “Saving...”** chrome before progress/stats/teardown so leave is not a frozen book page with no feedback.
- Stats leave path: **single `stats_v6` flush** when tracking is on (progress % + session merged); tracking off still writes progress % only when it changes.
- **LoadForBook memo:** save updates the memo slot for that book only (no wipe of all eight slots).

### Stats / progress (behavioral notes)

- **`progress.bin`:** resume position (spine/page); still written on real page changes and exit (crash-safe atomic write).
- **`stats_v6.bin`:** per-book analytics **and** home progress % (`progressPercentMilli`). Tracking off still may write this file for home bars—not “session tracking,” despite the `STATS` log tag.
- Format unchanged for CrossInk dual-path load; #1/#2 save/memo changes do not alter on-disk layout.

### Sleep / Quick Resume

- **No “Saving...” on sleep.** Back→Home still shows Saving before progress/teardown; power sleep, timeout sleep, and Quick Resume skip that popup so the page/moon/wallpaper is not interrupted.

### Earlier v0.1.8 branch work (rivulet / stability)

Also in this train of builds (not all listed as separate product features above):

- Rivulet layout core: section incremental build, partial caches, style resolve ladders.
- Image/ZIP loan and full-page image handling fixes.
- Scene-divider / rule width-height, drop-cap false-positive fixes.
- Home snappiness experiments (FAST resume) later revised to HALF-on-resume for cleanliness.
- Sleep PNG / wallpaper path improvements; dictionary line-loss fixes (as landed on the branch).
- Lexend font headers; Bitter removed from the linked built-in set (flash savings vs prior multi-family builds).

## Performance / UX takeaways (measured)

| Path | Rough cost | Notes |
|------|------------|--------|
| Warm open (snappy) | ~1.5–1.7 s to first ink | book.bin + FAST panel dominate |
| Warm page turn (forward) | ~580 ms | ~430 ms X3 panel floor |
| Back→Home | ~1–4 s wall | Exit SD + Saving chrome + HALF multi-stage busy waits |
| Menu/Settings → Home | Much faster | No EPUB teardown / stats flush |

Panel `Wait complete: X3_DRF` times can exceed the **visible** flash duration (BUSY settling after ink looks done).

---

## Flash / install

1. Flash `Casper-v0.1.8.bin` (or OTA asset matching tag `v0.1.8`).
2. First boot may migrate reader size enum and slim built-in font settings.
3. Existing `section.bin` entries are invalidated if font id/size/layout settings change—expect one rebuild per spine after font swaps.

---

## Not in v0.1.8 (deferred)

- Bidirectional idle glyph prewarm (reverse turns).
- Debounced `progress.bin` mid-session (kept every-turn + exit for safety).
- Coarse “only write stats if % moved ≥ 0.5%” (would hide single-page bar updates).
- Deferred progress write until after Home paints (rejected for crash/OOM risk).
- Full stats schema rewrite / progress-only file when tracking off (candidates for later).
- Structural glyph-blit / RAM page LRU engine work.
