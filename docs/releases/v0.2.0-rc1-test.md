# Casper v0.2.0-rc1 — device test candidate

Branch: `fix/casper-stability-v0.2.0-candidate`. Not a stable release.

## Source foundation

Preserves the September Casper source at `af10aa45` (including its existing Bare/dark-mode/reading/sleep behavior) and Grok's pinned FreeInk SDK update to `5deb923c33d97f918227b2ad983fda4d5a63c6ae`. No intended theme geometry, navigation menu, or product-statistics policy redesign.

## RC1 changes

- Real allocation-failure handling for Rivulet chapter metadata, page maps, page spans and owned text. No allocator-probe-only guarantee for those containers.
- Resumable token window instead of tokenizing every remaining word in a long paragraph for each page.
- UTF-8-safe run splitting at the 16-bit run-length boundary; explicit incomplete-source marking when HTML conversion stops at a prefix.
- Strict cached IR/map/page validation; incomplete chapter data cannot be published as a complete chapter cache.
- Exact previous-chapter ending from saved map checkpoints; no best-effort middle-of-chapter page presented as the ending. The same layout implementation is used for counting and painting.
- Render-key paragraph spacing invalidation, and corrected Literata 10pt relative-size lookup.
- Bounded multi-font/style prewarm requests that accept valid negative font IDs; cleared borrowed ligature pointers on SD font cache release.
- Incremental font-catalog parsing from SD, with checked catalog allocations.
- Staged font-family updates with rollback and interrupted-publication recovery. Failed or cancelled transfers preserve the existing installation.
- Shared graphics/font-cache handoff before network entry; reader state and cache mutations excluded from concurrent rendering.

## Validation and limits

The additional test runner compiles actual Rivulet, font-cache and JSON-parser source against deterministic host HAL/font stubs. It uses AddressSanitizer and UndefinedBehaviorSanitizer and allocation-failure injection. It is not a hardware speed or ghosting benchmark. The normal CMake suite and a full PlatformIO C3 build are required independently.

This is not yet a complete SD-paged chapter engine: the existing whole-chapter HTML/IR size and memory limits remain. Background indexing inherits the newer Casper scheduler and still needs device validation under random navigation. A cold unindexed previous chapter can still require forward layout to discover its exact ending; a failed or partial result is not silently accepted. Large or unusually complex books may still need further work.

TLS server-verification and full update-security hardening remain open; use the SD-card updater for initial candidate installation. Do not regard a successful Wi-Fi update as a security validation.

IR/map/page cache versions change; their first use may rebuild derived data. Resume/bookmark/stat files are not intentionally cleared. Back up the SD card before testing. Do not erase user data as a first troubleshooting step.

## Device acceptance

1. Confirm the displayed version/build ID and capture the startup hardware/panel identification log.
2. Open a known failing book, jump from chapter 1 to 15, go back to the final page of 14, then back and forward repeatedly. Check the actual last/first text against the EPUB.
3. Repeat after sleep, reopen, a font-size change and an orientation change; verify the content position.
4. Keep a chapter open while reading; inspect completion of its page count, then jump elsewhere and repeat.
5. Compare Bare Home, menus, chapter titles/artwork, drop caps and the Alice illustration/table cases with the established appearance.
6. Download a font; cancel or interrupt a replacement and verify the previously installed family survives. Reconnect Wi-Fi after a long reading session.
7. Test X3 with tracking on/off and X4 with its existing statistics restriction. Do not re-enable unavailable date-based reporting.
8. Record reset/crash logs, visible ghosting or extra flashes, and whether a failure happened cold or after a long session.

A successful compile is not a stability certification. Merge/release approval remains with the owner after device testing.
