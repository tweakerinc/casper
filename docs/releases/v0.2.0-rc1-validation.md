## Tests

The dedicated actual-source Rivulet/FontCacheManager/streaming-manifest suite passed **778 assertions** under AddressSanitizer/UndefinedBehaviorSanitizer with deterministic font/storage stubs and injected allocation failures. It includes a 12,000-word paragraph spanning 100 pages with identical counting/painting boundaries, IR/map persistence, malformed input, exact checkpointed chapter ending, and signed font IDs.

The first full CMake run passed 383 of 384 tests. Its sole failure expected old IR versions 19-26 to remain accepted. That expectation conflicts with the intentional v27 safety boundary: old caches may contain unmarked prefix-only conversions. Commit `f76c4fd` updates the test to require rejecting those versions while preserving source/user data. No firmware source was changed by that test correction. This commit reruns the full suite against the corrected expectation; consult the resulting Actions run for its actual result.

Seven additional local fault-injection scenarios exercised the real FontInstallTransaction header against a simulated filesystem: cancellation, successful publication, rename failure at either stage, recovery after interrupted publication, invalid family, and invalid/truncated destination paths. These are not physical SD-card power-cut tests.

## Before device testing

Back up the SD card including hidden folders. Install the `.bin` through the existing SD Firmware Update flow. Retain the known-working firmware for recovery. Derived Rivulet caches rebuild once; progress, bookmarks, font preferences, theme geometry and the X3/X4 statistics policy are not intentionally reset.

Test chapter 1 -> 15 -> last page of 14, repeated reverse/forward turns, sleep/resume, font/orientation changes, Bare cover return, and cancelled/interrupted font updates. Capture startup panel identification and the build ID with any failure.

## Not claimed complete

The full SD-paged content engine, arbitrary-size-chapter ingestion, comprehensive bidirectional book-wide scheduling, and all networking/security/refresh work are not finished. The existing resident chapter limits remain. TLS server-authentication hardening remains open; initial candidate installation should use SD rather than Wi-Fi OTA. On-device performance, ghosting, battery behavior and long-session stability still require testing.
