# Casper v0.2.0-rc2 — indexing/readiness test candidate

Candidate branch only. No stable/main merge. This changes the reader's storage and scheduling, not its UI/theme layout or X3/X4 statistics policy.

## Implemented

- Full-source XHTML ingestion through a fixed sliding input window. No chapter-sized HTML allocation and no prefix-only chapter accepted as complete.
- SD-backed block/run/text working sets and page-start maps. Canonical IR is published in resumable chunks; current and preparation engines have independent ownership.
- Initial open and requested chapter navigation use a cooperative preparation session. Background preparation does not evict the chapter on screen.
- Readiness priorities: the previous chapter, next chapter, then the rest of the book. Exact previous-chapter endings require a completed verified layout, not an estimate.
- Partial page-map checkpoints survive cancellation, sleep and reopening. Completed per-chapter counts accumulate in a checksummed per-layout SD ledger; exact book totals are shown only when every chapter is known.
- Content anchors use two checksummed persistent slots outside disposable caches. Font/orientation reflow resolves the saved content cursor rather than scaling an estimated page number. A failed orientation reflow retains the old engine and restores its orientation.
- Random page, percent and chapter requests publish the destination only after it exists. Go-to-start/next/previous failure paths preserve the visible page. Replacement-book fingerprints include ZIP entry CRC metadata.
- Parser text allocations check their actual allocation results. Speculative page buffers can be released independently of the visible page.

## Verification

The host regression runner compiles the real parser, storage windows, page layout, engine and readiness coordinator with deterministic font/HAL stubs. Tests cover streamed-versus-memory text and page equivalence, >192KiB text with thousands of blocks, chunked publication, chapter 1 -> 15 -> verified ending of 14, cancellation, allocation/read/write failures, checkpoint reuse, content-anchor reflow, exact percentage landing, torn anchor writes, and same-size source replacement. Run `python3 tools/casper_stability/run_tests.py`. The regular CMake suite and production PlatformIO C3 compilation must also pass; host assertions alone do not prove device performance or visual quality.

## Remaining boundaries / device testing

- Existing parser styling rules remain; this does not add a full browser CSS engine. Compare chapter art/drop caps/spacing and the actual Alice EPUB against the established appearance.
- Source parsing is incremental but a complete chapter representation is prepared before its first page is published. EPUB ZIP extraction remains entry-scoped, with cancellation checks in output chunks. A cold unindexed chapter's exact ending still requires forward pagination from its last checkpoint.
- Bounded per-chapter format limits are 32MiB text, 65,534 blocks/runs, and 4KiB per run (long text is split safely); page maps support up to 1,000,000 page starts on SD. Oversized tags beyond the 8KiB parser window fail explicitly. ZIP64 is not added by this candidate.
- The Home-only indexer remains disabled by its existing product switch. Whole-book work now runs while the reader is idle; it does not keep the device awake solely to finish indexing.
- This does not complete the separate Wi-Fi/OTA security or panel waveform audit. Initial installation should use the SD updater. No measured on-device speed, battery, ghosting, or crash-free claim is made.
- Back up the SD card and keep RC1/known-good firmware. IR/map/page caches rebuild once; user progress, bookmarks, statistics, themes and preferences are not intentionally erased. New anchors are retained when derived caches are cleared.
