# Casper v0.2.0-rc3 — field-regression repair candidate

Candidate branch only; not stable or hardware-certified. UI theme geometry,
menu appearance, selected user fonts, and X3/X4 statistics policy are retained.

## Changes

- Respect ordinary div/body/section/article block boundaries; retain inherited
  inline styles without concatenating separate paragraphs or chapter headings.
- Discover linked and embedded chapter stylesheets. Parse a bounded subset of
  tag/class/id selectors and cascade specificity using the existing CssParser.
  Apply alignment, relative size, emphasis, text decoration, vertical scripts,
  indent and block spacing. Do not fetch network styles while reading.
- Keep whitespace at parser chunk/style boundaries. Preserve entity punctuation.
  Bump IR to v29 and page cache to v7; include all layout fields and IR generation
  in the page-cache filename fingerprint so flattened old pages are not reused.
- For sparse publisher navigation, retain explicit TOC anchors and expose omitted
  spine sections in reading order. Unknown headings use the localized Section N
  label, not an invented chapter number. After preparation, short actual headings
  are saved in source-scoped, checksummed bounded records for later menu visits.
  Expansion is bounded to 2,048 combined entries; larger lists retain the TOC.
- Repair progressive JPEG coefficient spill files for FAT-style seek semantics:
  explicitly fill unallocated gaps, propagate real I/O failure, and avoid forcing
  a metadata flush on every coefficient row. Preserve the full luma output.
- Route progressive JPEGs directly to the full-resolution spill decoder instead
  of first invoking the unsupported JPEGDEC fallback. Correct decoder alignment,
  negative signed shifts, and AC/DC row-cache pointer invalidation. Add a pinned
  JPEGDEC patch guarding short Huffman prefix shifts for baseline images.
- Admit new background preparation only with headroom for the actual inflater,
  after a quiet period. Reclaim optional prefetch/glyph storage first; do not
  immediately refill it while the preparation worker owns that budget.
- Defer optional page-cache and stat/map publication until after a ready page can
  paint. Avoid rewriting unchanged checkpoints and duplicate first/tail pages.
- Yield and service the watchdog during ZIP output chunks, not only before and
  after an entire entry. Keep the known RC2.1 safe file-close implementation.

## Local verification before CI

The regular host suite passed 395 tests. The existing Rivulet sanitizer suite
passed 3,538 assertions. Actual HAL cleanup and retry-policy tests passed.

New integration tests compile the production ChapterLoader, parser, paged IR,
layout and storage adapter. Fonts, ZIP transport and image geometry are explicitly
mocked in that loader harness. A separate cover harness compiles the production
JpegToBmpConverter, jpgd, pinned JPEGDEC and actual storage adapter, with mocked
SdFat/RTOS below the adapter and FAT-style rejection of seek past EOF.

With the privately supplied EPUB, all 126 spine sections passed cold/warm
conversion and first-page-cache tests (7,884 blocks, 9,289 runs, 1,105,152 text
bytes). Its progressive cover's 1,407,000 luma pixels matched the resident decoder
reference exactly; production Bare and sleep conversion yielded valid 2-bit BMPs
350x560 and 495x792. No private book, prose or cover is added to the repository.

The integration suite also tests synthetic books, baseline/progressive public
fixtures, corrupted spill reads/writes, and the original failing sparse-file
operation. Host timings are not device benchmarks. No watchdog stack was captured
in the field report, so the exact watchdog-triggering instruction is not proven.

## Limits and device acceptance

This is not full browser CSS. Descendant/pseudo selectors, @import/media cascade,
all font-family rules and arbitrary web layout remain outside this subset. A
cold chapter still completes conversion before first-page publication. First
cover conversion can take time and needs SD scratch space; later opens reuse
its normal cache. Exact previous-chapter endings still require forward layout
from available checkpoints. Do not infer measured device speed or battery gains.

Back up the SD card and keep a known-working firmware. Use the existing SD updater
with stable power. Do not factory-reset. Old derived IR/pages rebuild automatically;
progress, bookmarks and stats are not intentionally erased. New paragraph boundaries
may change old text-derived anchors, so verify the last reading location on first
opening after this repair. Capture an incorrect resume rather than deleting data.

Test the failing EPUB's recap, interlude, first numbered chapter, chapter artwork,
Bare and sleep covers, ordinary rapid turns, a chapter jump/backward boundary,
and sleep/font/orientation resume. Capture version/build and logs with failures.
Production-build and CI success must be checked independently before distributing
a binary; this source note alone does not assert a passing firmware build.
