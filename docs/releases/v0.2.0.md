# Casper v0.2.0

**Product:** Casper  
**Based on:** CrossPoint Reader 1.5 & CrossInk  
**Devices:** Xteink X3 & X4 (one binary for both)

**Firmware:** `dist/Casper-v0.2.0.0001.bin` (tag `v0.2.0` when you publish GitHub)

This is a field build on top of the **v0.1.9 you already shipped** (`Casper-v0.1.9.0010.bin`, GitHub asset `Casper-v0.1.9.bin`, SHA256 `fd02d1ee…b84f`, compiled 2026-09-01 08:13 UTC). Ship it, then wait for reader feedback before the next train.

---

## Highlights

v0.2.0 is only the work **after** that 0010 ship:

- **Chapters stay readable** — existing CrossPoint / CrossInk chapter caches load; sitting open converts a prefix instead of failing as **Chapter not readable**
- **Home Back never re-decodes JPEG** when any cover thumb is already on SD (560 / 280 / 168). No silent 280→560 “tiny then bigger” on Back
- **Rendering Cover** in the upper left while a missing jacket JPEG runs (light and Dark Mode)
- **Fonts over WiFi work** — catalog is the live `crossink-fonts` bucket (0010 still pointed at a missing `legacy-fonts` bucket)
- **WiFi firmware update can finish** — no full e-ink refresh during the GitHub TLS download; retries; framebuffer loan

Dark Mode through Bare, Hail Mary titles + drop caps, last-frame sleep, X4 Home chrome, music notes, and X4 clipping underlines were **already in 0010**. They are unchanged here.

## What’s New (after v0.1.9.0010)

### Chapters stay readable

0010 could still treat a still-good CrossPoint / CrossInk chapter cache as unusable and then run out of RAM converting it again. v0.2.0:

- Loads chapter IR **v19–v26**. A cache that is merely an older CrossPoint format is **not** treated as corrupt.
- Sitting open **must** produce IR when the EPUB has HTML: framebuffer loan covers cache + convert, HTML is converted in a prefix, extra convert retry on sitting loads.
- Sibling `sN_m{0,1,2}.rvir` files are used. A partial convert does **not** wipe a good `.rvir`.
- Fail string is still **Chapter not readable** — it should fire far less often.

**Try:** books that used to fail on first open of a chapter, and books already laid out on a CrossPoint / CrossInk card.

### Home covers on Back

0010 already blitted a cached **560** Bare cover. v0.2.0:

- If **any** cached thumb exists (560 / 280 / 168), Back / Home **blits it**. JPEG decode is not on the Back path.
- After the shell is on glass, a missing 560 (cache delete, or only a leftover 280/168) generates with upper-left **Rendering Cover** (same corner as Opening / Saving). Dark Mode uses HALF so the word is light on dark.
- Gen loans the 48 KB framebuffer so fragmented heap after reading can still decode. Field logs of `thumbs_missing` then 60s of silence (`bw_no_path`) were the 90/80 KB heap gate plus a cue that never refreshed.
- Idle may upgrade a leftover 280 to 560 **with that cue** — not a silent tiny-then-bigger on Back.

**Try:** delete a book cache on Bare, stay on Home. You should see **Rendering Cover**, then the jacket. Empire of the Vampire as Sleep → Cover is a full-panel grey pass (crisp). A muddy Home jacket after cache delete was often the missed JPEG, or a leftover 280. Progressive cover JPEGs still decode at 1/8 (Enable Logging: `Progressive JPEG decode uses 1/8 source`) — that is a remaining softness vs a baseline JPEG like many Empire files.

### Fonts over WiFi

0010’s Manage Fonts download pointed at `legacy-fonts` (S3 `NoSuchBucket`, HTTP 404). v0.2.0 uses the live catalog:

`http://crossink-fonts.s3.us-east-1.amazonaws.com/sd-fonts-m1-b4/fonts.json`

**Try:** Settings → Manage Fonts → download a family over WiFi.

### WiFi firmware update

- No full e-ink paint during the ~5.4 MB GitHub TLS download (that paint was aborting the transfer).
- Framebuffer loan + **3 retries**.
- A GitHub release with no matching `.bin` reports **No update available**, not **Update failed**.

**From a v0.1.9 device, Check for updates only offers v0.2.0 after you publish GitHub tag `v0.2.0`.** The dist filename is `Casper-v0.2.0.0001.bin`. You can also attach `Casper-v0.2.0.bin` (same bytes) on the GitHub release; both names are valid OTA assets.

A device already on `v0.2.0` against tag `v0.2.0` correctly reports no update.

## How to Install

1. Flash `Casper-v0.2.0.0001.bin` (or `Casper-v0.2.0.bin` if you copy the same bytes onto the GitHub release).
2. **X4:** after flashing, use **Reset → Power** so the new image actually boots (unplug/replug alone is often not enough).
3. Book cache layout is unchanged: `/.crosspoint/epub_<hash>/`. There is no SD migrate for this release.

### CrossPoint web flasher (recommended)

1. Download **Casper-v0.2.0.0001.bin** from the release (or the matching `Casper-v0.2.0.bin`).
2. Connect your **X3 or X4** via USB-C and wake/unlock it.
3. Open [https://crosspointreader.com/#flash-tools](https://crosspointreader.com/#flash-tools) (Chrome / Edge / Firefox on desktop).
4. Select **Xteink X3** or **Xteink X4**.
5. Click **Custom .bin** and choose the file.
6. Flash, then reset/wake the device if prompted.

### SD firmware update

Copy `Casper-v0.2.0.0001.bin` (or `Casper-v0.2.0.bin`) to the root of the SD card → **Settings → System → SD Firmware Update**.

### WiFi OTA (after the GitHub tag exists)

On a **v0.1.9** device: **Settings → System → Check for updates**. The device only sees this build once tag `v0.2.0` is published with a `Casper-v*.bin` asset.

## Not in v0.2.0 (deferred)

- Whole-book Home indexing (still disabled; it froze the UI).
- Font Darkness / ink-weight sliders (AA on/off + Mild raster are the controls).
- Windowed greyscale in the display HAL (clock AA is still a full-frame grey pass).
- PNG decoder lifetime: the decoder can still sit warm at ~50 KB. Next efficiency pass, not this ship.
- DCC `[ 70 ]` drop-cap arming.
- `book_<id>/package` cache rekey (abandoned; CrossPoint / CrossInk folders stay).
